Current agreed v1 assumptions
-----------------------------
- Galcon will live under zoo/board_games/galcon/.
- Tests stay under zoo/board_games/galcon/envs/.
- Initial planet count: num_planets = 8.
- One tick is tick_seconds = 0.25 simulated seconds.
- The game is turn-based for LightZero compatibility.
- Each player action advances the simulation by one tick.
- Discrete action space:
  - action 0 = pass
  - actions 1..N*N = source-target send action
  - source/target are decoded from action - 1
- Send ratio is fixed at 50%.
- min_send_ships = 1 initially.
- Ships are floats internally.
- fleet_speed = 40.0 coordinate units per second.
- Initial K = 16.
- Initial num_simulations = 50.
- Start with seeded random maps.
- Use grid-based observations later.
- Do not finalize model design until grid observation spec is defined.

Finalized Phase 3 action / observation design decisions
--------------------------------------------------
- The map is represented as a fixed grid.
- Each grid square covers 20x20 world-coordinate units. This is because planets have a min radius of 12 with a spacing of 6.5 to allow ships through.
- The grid must be large enough to cover:
  - both home planets
  - all neutral planet spawn locations
  - expected fleet movement between planets
- Action space uses grid-square source and target locations:
  - action 0 = pass
  - actions 1..G*G*G*G encode:
    - Source_X
    - Source_Y
    - Target_X
    - Target_Y
  - Send percentage remains fixed for now.
  - Percentage may become an explicit action component later.
- Source_X, Source_Y, Target_X, and Target_Y are decoded mathematically from the action id.
- If the selected source grid square contains one or more friendly planets, the send action uses the planet in that square as the source.
- If the selected source grid square does not contain a valid friendly planet, the action is illegal and should be masked out.
- If the selected target grid square contains a planet, the action targets that planet.
- If the selected target grid square does not contain a planet, the action is illegal and should be masked out.
- Fleet redirection is deferred:
  - future action design will add an additional action layer with the same grid dimensions
  - selecting a fleet-redirection source grid square will redirect all friendly fleets present in that square to the selected target square
- Observation space is a channel-first grid tensor:
  - shape = (channels, grid_height, grid_width)
- X/Y grid-square coordinates are not included as channels because position is implicitly encoded by grid location.
- Planet channels per grid square:
  - planet local x offset within the 20x20 grid square
  - planet local y offset within the 20x20 grid square
  - planet production
  - planet radius
  - planet ships encoded linearly
  - planet ships are broken up into 3 channels: friendly_ships, enemy_ships, neutral_ships
- Fleet channels per grid square use K = 3 top fleets per side.
- For each grid square, encode friendly fleets:
  - largest K friendly fleets in descending ship count order
  - one additional summary slot for all remaining smaller friendly fleets
- For each grid square, encode enemy fleets:
  - largest K enemy fleets in descending ship count order
  - one additional summary slot for all remaining smaller enemy fleets
- Each individual fleet slot encodes:
  - target x
  - target y
  - fleet radius
  - ship count encoded linearly for now
  - time-to-land or distance encoded linearly
- Remaining-fleet summary slots encode:
  - sum of ship counts
  - ship-weighted average target x
  - ship-weighted average target y
  - ship-weighted average time-to-land or distance
  - ship-weighted average radius
  - then normalize ship/time-or-distance fields as appropriate
- Each grid square containing a planet also includes a future fleet landing schedule.
- Future fleet landing schedule time buckets:
  - [0, 1]
  - [1, 2]
  - [2, 4]
  - [4, 6]
  - [6, 8]
  - [8, 10]
  - [10, infinity)
- For each landing schedule bucket, include four linearly-encoded / normalized ship channels (normalizing by 250 for now):
  - friendly ships landing
  - enemy ships landing
  - max(friendly ships - enemy ships, 0)
  - max(enemy ships - friendly ships, 0)
- Landing schedule ship counts use the same linear ship encoding initially:
  - ships / 250
